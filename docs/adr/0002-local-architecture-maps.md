# ADR 0002: локальная архитектура и ограниченный контекст

Статус: принято по требованию владельца 22.10.2026.

## Решение

Код группируется по ответственности: `src/core/{machine,visual,placement}`,
`src/ui/{shell,editor,contract,scene,shared}`, локальный сервис в `src/service`,
инструменты проверки и Git в `tools`, тесты повторяют границы компонентов.
Машинная семантика, визуальная компиляция и конкретный Linux-алгоритм различаются;
браузер, HTTP, MCP и файловое хранилище остаются внешними владельцами эффектов.
Публичный index допустим как вход компонента, старые пути-фасады не сохраняются.

Направления импортов проверяются по владельцам: `machine` не зависит от
`visual/placement`, `visual` может использовать `machine`; `placement` связывает их.
В UI общие элементы `shared` не знают фич; `editor/contract/scene` используют свой
компонент, shared и core; `shell` собирает их. В service `http` использует store,
store — native и core; native и MCP не зависят от HTTP/store. MCP ходит через API.

Каждая собственная папка имеет короткий `AGENTS.md`: назначение, границы,
зависимости и карту непосредственных файлов/дочерних карт. Агент читает путь
от корня к нужному владельцу, а не все описание проекта сразу. Ответственность
элемента указана в родительской карте; общий текст не копируется вниз.
Первичные источники Linux и генерируемые данные не получают искусственных карт.

## Контроль

Gate проверяет полноту карт, существование ссылок, новые неописанные файлы/папки,
размер контекста (80 строк / 6000 символов на карту), не более 12 файлов и 12
дочерних папок на уровень (24 файла для конфигурации корня). Предел исходника —
600 строк, тестового файла — 700; ориентир для компонента — до 400 строк.
Эти ограничения дополняют проверку зависимостей, циклов, сложности и ревью.
Механическая нарезка файла ради лимита не является корректной декомпозицией.

## Сохранение поведения

Не меняются контракты алгоритма, байты Linux, u32/u64 и флаги, хранение черновика,
единообразие визуальных примитивов, HTTP/MCP authority и обязательность CI.
Перенос путей требует обновить импорты, сборку, allowlist сервера и тесты.
CSS делится по владельцам с сохранением каскада; визуальный результат проверяется.
