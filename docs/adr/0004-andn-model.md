# ADR 0004: ANDN в ограниченной ASM-модели

Статус: реализуется по сообщению об ошибке от 22.10.2026; принятие релиза остаётся за владельцем.

## Причина

Редактор отклоняет `andnq %rax, %rbp, %rbp` как неизвестную операцию.
Машина умеет только одно- и двухоперандные арифметические инструкции.

## Решение

Добавить регистровые формы `andnl` и `andnq` в существующую ISA.
В AT&T запись `andnq %a, %b, %d` означает `d = (~b) & a`.
Оба источника читаются до записи назначения; прежнее значение отдельного
назначения не требуется. Запись u32 обнуляет старшие 32 бита, CF сбрасывается,
ZF отражает нулевой результат. Остальные флаги модель не представляет.
Неверное число операндов, смешанные ширины, immediate и память отклоняются.

Визуальный импорт использует существующие шаблоны присваивания, НЕ и И;
дополнительный тип блока и версия черновика не нужны. Обратная компиляция
может выдать MOV/NOT/AND и дополнительные временные регистры. Их эффекты
учитываются действующим механизмом; сохранение одной инструкции ANDN
или улучшение производительности не заявляется.

Границы компонентов, Linux-контракт, пользовательские черновики и фиксированный
Rust harness сохраняются. Кандидат остаётся чистой арифметической моделью:
поддержка BMI1 процессором и загрузка ядра этим изменением не проверяются.

## Проверка

Регрессии проверяют порядок источников, алиасы назначения, чтение до
инициализации, края u32/u64, CF/ZF, ошибки форм, импорт и сериализацию Blockly,
а также фрагмент со скриншота и вариант выравнивания с правильным порядком.
Обязательный общий gate — `npm run quality`.

Семантика: [Intel SDM, ANDN](https://cdrdv2-public.intel.com/671110/325383-sdm-vol-2abcd.pdf),
порядок операндов: [GNU as, AT&T Syntax](https://sourceware.org/binutils/docs/as/i386_002dVariations.html).
